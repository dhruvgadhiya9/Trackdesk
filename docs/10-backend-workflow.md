# Backend Workflow (contract-first, Spring Boot)

Reference module: **`com.trackdesk.customers`**. Copy its shape exactly.

## The 7 steps
1. **Spec.** Edit `packages/contracts/openapi/<module>.yaml`: paths, schemas, `x-roles`, Problem
   Details error responses. If permissions change, update `packages/contracts/permissions.yaml`.
   Run `pnpm contracts:generate`. This regenerates the TS client/Zod, `Permission.java` and
   `R__role_permissions.sql`. Java interfaces are regenerated by Gradle `openApiGenerate`,
   which runs before `compileJava`.
2. **Migration.** Add `V<n>__<module>.sql`: table with `tenant_id`, `unique (tenant_id, id)`,
   composite FKs, an index leading with `tenant_id`, `enable` + `force row level security`, policies,
   and grants to `trackdesk_app`. Add rows for the new table to
   `src/test/resources/isolation/seed.sql` (the isolation suite fails if you forget). Mark
   `-- SECURITY-REVIEW-REQUIRED:`.
3. **Module.** Create `com.trackdesk.<module>` with:
   - `domain/` entity extending `TenantScopedEntity`, with domain rules and events
   - `infrastructure/` Spring Data repository (the only place queries live)
   - `application/` service (`@Transactional`, `@Audited`) and MapStruct mapper
   - `api/` controller `implements <Module>Api` with `@PreAuthorize("hasPermission(null, T(...).X)")`
4. **Business logic.** Rules live in `domain/` as plain Java with unit tests. A senior human
   designs anything listed below.
5. **Adapters.** External calls go behind a port interface in `application/` with an adapter in
   `infrastructure/`, plus a fake for local/test.
6. **Integration tests.** One `@Nested` test per Gherkin scenario, extending `IntegrationTest`
   (Testcontainers postgis + Flyway). Also add the endpoint to `CrossTenantApiTest`; the coverage
   test fails if an implemented endpoint is missing.
7. **PR.** Fill in the DoD template, run `./gradlew build` and `pnpm turbo run lint typecheck test`,
   and list the security-sensitive files in REVIEW-QUEUE.md.

## Areas where a senior human must design
- Tenancy, RLS policies, the `set_config` wiring and any privileged/SECURITY DEFINER function
- Auth and JWT claim mapping, role and permission matrix changes
- Job state machine transitions and SLA rules
- Dispatch assignment rules
- Offline sync conflict strategy and idempotency
- Payment flows, refunds, webhooks, VAT and rounding rules
- Happy Code OTP security (hashing, rate limits, attempt limits)
- Compliance certificates (content, immutability, retention)
- Location data: consent, working-hours gating, retention
- Data deletion and export (UK GDPR)
